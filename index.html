AlphaZero Connect 4 bot 2026

A Connect 4 bot that learns by playing against itself, based on the AlphaZero paper. I built it in four steps: the game itself, minimax with alpha-beta pruning, Monte Carlo tree search, and then a neural network trained on its own games with PUCT search on top. Each new network has to beat the previous one in a match before it gets kept.

This is the actual trained network running in your browser with onnxruntime-web. There's no server. Open it full size if the board is too small.

Play it in your browser

  • After about 16 hours of training on my laptop's GPU, the network plus search beats my alpha-beta engine at every depth I tried (0.78 score against depth 6 over 30 games with random openings).
  • I measure how good it is by comparing its moves to a perfect Connect 4 solver on 6,000 test positions. The self-play network got stuck at around 26.5% wrong moves.
  • I wasn't sure if that was because the network was too small or because it didn't have enough training data, so I trained the same network on 300k positions labeled by the solver instead. That got it down to 7.4%, so the problem was the data, not the network.
  • Early on my results were inflated because two deterministic bots play the exact same game every time, so a 12 game match was really 2 games. All matches use random openings now.
  • 291 pytest tests. The JavaScript version is tested against the Python version on 120 positions to make sure they play the same moves, and the ONNX exports are checked against PyTorch.

Python, PyTorch, NumPy, pytest. Browser version in JavaScript with onnxruntime-web. Code and writeup on GitHub

  • Co-designed the router: a 9-stage pipeline in Node.js that classifies each message by complexity and intent and sends it to either a fast model or a reasoning model through OpenRouter. It has an offline evaluation harness with unit tests so we can check routing changes before shipping them.
  • Built the retry and reliability layer for the model providers: exponential backoff with jitter, retries before the stream starts, per-provider failure tracking, and a retry button in the client, so users still get a response when a provider returns 429s or 5xx errors.

  • Shipped compliance and growth features end to end: server-side geo-restriction for EEA, UK and Switzerland, terms and privacy pages with age gating, and a sitemap and metadata for SEO.
